Your first PR

Four steps. No Xcode.

All you need is macOS 15 or later and Apple's Command Line Tools. Click a step to see the commands.

  1. Get the tools and the code

    Install the Command Line Tools, fork the repo on GitHub and clone your fork.

  2. Build and run it

    build.sh builds a release app, installs it in ~/Applications and opens it. Look for the icon in your menu bar.

  3. Make a change, run the tests

    Logic goes in ClipnpasteCore with a test beside it. test.sh runs the swift-testing suite with only the Command Line Tools.

  4. Open a pull request

    One change per PR, a sentence on why, and a GIF or screenshot if it touches the UI.

    House rules
    
What we protect.

    
A clipboard holds passwords, messages and private photos. These rules keep it trustworthy, and PRs are reviewed against them.

  

  

    
Local only.
Clips never leave the Mac. The one allowed request is the GitHub update check, and it carries nothing about the user.

    
Zero dependencies.
Apple frameworks and the system SQLite. If you need a library, write the small part you need.

    
Calm motion.
Springs with no overshoot. Respect Reduce Motion everywhere.

    
Never steal focus.
The panel must never activate itself over the app you are pasting into.

    
Test the core.
Logic in ClipnpasteCore ships with a test. UI changes ship with a GIF.

    
Plain words.
Copy in the app and docs is short, literal and friendly. No jargon.

    Contributor FAQ
    
Questions, answered.

  

  

    
Do I need Xcode?
No. The Command Line Tools are enough (xcode-select --install). scripts/test.sh points SwiftPM at the Testing framework that ships with them.

    
Why does macOS forget the Accessibility permission after I rebuild?
Without a signing certificate, build.sh signs ad hoc, and macOS treats each ad-hoc build as a new app. Set CLIPNPASTE_SIGN_ID="Your Certificate" to sign with a stable identity of your own.

    
I'm new to Swift. Where should I start?
In Sources/ClipnpasteCore. It is plain Swift with no UI, every file has tests next to it in Tests/, and you can run them in seconds.

    
Can I add a dependency?
Please don't. Zero dependencies keeps the app small, auditable and safe for something that sees your clipboard. Open an issue if you think there is a real case.

    
Will you accept sync or cloud features?
No. Clipnpaste is local-only on purpose. Features that send clipboard data off the Mac won't be merged.

    
How big should a pull request be?
One change. If it touches the UI, attach a short GIF. If it touches the core, add or update a test. For anything larger than a bug fix, open an issue first.
